# Waves NS1：Suppression 0/50/100 自适应端点验证

## 结论

本机 Waves NS1 Stereo 12.7.0.209 VST3 已在 Ableton Live 11.3.43 / 48 kHz 中真实加载。界面只有 Suppression 推子和 Attenuation Meter；A: Default Preset 的推子为 0.0，宿主报告 0 samples。以同一实例的 0.0 为主参考，只把推子改为 50.0 和 100.0，所有先前链上设备均停用。

Suppression 50 对固定人声 21–42 秒整体为 -0.270638 dB，390 个活跃 50 ms 窗的中位为 -0.272 dB、P10 为 -0.389 dB，只有 2 窗达到 1 dB 衰减；同一条件对脉冲列、稳定多音、空间与动态区域分别为 -2.808、-1.978、-1.193、-0.257 dB。这证明推子驱动的是内容自适应分类，而不是恒定输出衰减。

Suppression 100 是破坏性压力端点：固定人声整体 -13.140719 dB，390/390 个活跃窗都至少衰减 6 dB，中位 -14.322 dB；稳定多音和脉冲列分别 -16.438/-21.704 dB。100 不是“更干净”的推荐值，而是算法可能把有效前景一并移除的明确风险边界。

当前 Composite 没有专门叠加已知电平的白/粉/风扇噪声，因此本轮 L3 证明的是本机实例、零延迟、推子标度、节目相关衰减和人声损伤端点；不把它写成特定噪声 SNR 改善量。

## 0% 控制边界

Suppression 0 相对较早共享旁路在五个区域的电平差为约 -0.077 至 -0.000 dB，但独立保存的宿主状态无法可靠 Null，相关/残差也不支持逐比特透明结论。因此 50/100 的主比较统一使用同一已插入实例的 0% 渲染；0% 只记为电平近似中性控制，不写成完全透明。

## 操作与工作流

- 先把推子置 0，循环“只有噪声、最弱有效字尾、呼吸/擦音、正常强度语句”四类片段，再缓慢上推。推子数字是强度，不是目标衰减 dB。
- 在编曲中噪声刚退到遮蔽下就停止；独唱时若高频变空、尾音像门控或 Attenuation Meter 在有效音节上持续深动，立即回退。
- 当前 50 端点对固定人声整体较轻，但仍对高频区域变化更大；它不是所有录音的推荐起点。更低 SNR、更多房间反射或伴奏泄漏会改变分类。
- 100 端点明确会移除有效人声，不应用来追求“绝对静音”。严重/变化快/音乐性噪声应转到可学习噪声轮廓或频谱修复工具。
- 放在重压缩、MV2、Vocal Rider、激励与饱和之前；后级会把残余噪声和伪影一起放大。与 Gate/Expander 分工：NS1 处理连续噪声，Gate 只控制句间。

## 边界与未验证项

- 未叠加已知 SNR 的白噪、粉噪、风扇或变化房间噪声，不能给出噪声改善 dB、SNR 或伪影阈值。
- 未验证 Mono、VST2、其它采样率、左右内部联动、自动化、压缩前后顺序、动态房间反射、伴奏泄漏或盲听。
- 频带结果来自长窗区域能量，包含时间选择性，不能视为静态传递函数。
- Suppression 100 只用于确认风险边界，不代表推荐工作流。
