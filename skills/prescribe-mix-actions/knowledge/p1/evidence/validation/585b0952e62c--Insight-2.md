# Insight 2：默认计量、中性通道与累计窗口验证

## 结论

本机 iZotope Insight 2 VST3 在 Ableton Live 11.3.43 默认 Loudness + Levels 布局下，宿主设备栏报告 Latency 2399 samples（约 50 ms）。Ableton 的离线 PDC 补偿后，固定脉冲导出与独立旁通相比最佳整数延迟为 0 samples，直接相关 0.999999998922，RMS 电平差 -0.000000 dB；残差 RMS -141.469510 dBFS，落在两次独立 24-bit Triangular dither 的随机底噪边界。因此“导出对齐为零”证明 PDC 后中性，不代表插件自身零延迟。

实时播放从宿主 1.1.1 开始，在 2.1.1 进入 6 秒固定脉冲夹具；播放至 8.3.1 时，默认表显示 Integrated -41.2 LUFS、LRA 11.1 LU、True Peak -1.9 dB、Max Momentary -37.4 LUFS，左右 Peak 均 -1.9 dB。该组数字是稀疏脉冲验证窗的真实界面读数，只用于证明累计、峰值与窗口状态行为，不作为音乐响度目标。

## 固定状态与量化

- 插件：iZotope Insight 2，本机文件清单版本 2.0.6.0 / 2.6.0，真实实例标题为 `Insight 2`，VST3。
- 布局：默认 `Loudness` + `Levels`；未改 Targets、量程、Gate、标准或模块设置。
- 输入：`impulse_train_48k.wav`；Host 160 BPM；夹具位于 2.1.1；实时计量从 1.1.1 开始。
- 导出：Master、6 s、48 kHz/24-bit WAV、Triangular dither；工程快照 `validation/host/snapshots/585b0952e62c--Insight-2.als`。

## 操作观察与工作流

- 默认窗口把 Loudness 与 Levels 同时放在同一页，适合同时记录累计响度、LRA、True Peak、左右 Peak/RMS；读数必须连同 Reset 时点、播放起点和素材窗口一起保存。
- 顶部模块入口真实可见：扬声器/Levels、Loudness、Sound Field、History、Intelligibility、Spectrum/Spectrogram 等；本轮只量化默认 Loudness + Levels，不把其它入口的可见性当作校准通过。
- 稀疏脉冲结束后 Short-term/Momentary 会回到 `-Inf`，但 Integrated、LRA、Max Momentary 与峰值保持历史；因此静音后的“当前值”和累计值不可混写。
- 完成离线导出后，界面中的 Integrated、Momentary 与 LRA 回到 `-Inf/-Inf/0.0`，而 True Peak 与左右 Peak 仍显示 -1.9 dB。离线导出会改变计量历史状态，正式测量不应把导出后的窗口截图当作刚才实时播放的累计报告。
- 计量器虽然音频中性，也应放在 Monitor/Main/Vocal Bus 末端；保存工程快照不能代替导出前复核其当前布局、Reset 历史和 Relay 来源。
- Ableton 设备栏真实显示 `Latency: 2399 samples (50 ms)`；实时监控、并行链或跨轨 Relay 对齐必须依赖宿主 PDC 或人工补偿，不能从离线导出的 0-sample 残差反推插件零延迟。

## 边界与未验证项

- 本轮没有用官方校准文件或独立 BS.1770 / True Peak 实现交叉验证绝对读数；-41.2 LUFS 与 11.1 LU 仅为固定稀疏脉冲窗的界面观察。
- 未量化 Sound Field、Spectrum/Spectrogram、History、Intelligibility、Relay、多声道、Targets/标准切换或自动化。
- 两份中性对照均有独立 Triangular dither，随机抖动使 bit-identical 不成立；以零延迟、近 1 相关、零电平差和约 -141.5 dBFS 残差为通过依据。
- 结论只覆盖本机 VST3 / Ableton，不外推 Studio One 或文件清单中 2.0.6 与 2.6 的具体功能差异。
